# Jbot v1.0 운영 후보판(RC) 완성 마스터 플랜

이 문서는 "Jbot v1.0 운영 후보판 완성 마스터 실행 지시서"에 따라 장기 실행 작업의
현재 상태·목표 상태·단계 구성·의존관계·위험요소·외부계정 필요항목·이번 브랜치
범위 제외 항목을 기록한다. 세션이 끊기거나 컨텍스트 한도에 도달해도 이 문서와
`docs/JBOT_V1_EXECUTION_STATE.md`만 읽으면 새 세션이 바로 이어서 작업할 수 있도록
유지한다.

브랜치: `claude/jbot-v1-production-completion-v1` (base: `main`, PR #3 병합 이후 분기)

## 1. 현재 상태 (이 계획 수립 시점)

`main`에는 아래가 이미 존재한다 (PR #3 병합 완료):
- 핵심 RAG 파이프라인: 한국 법령 구조 파싱, 하이브리드 검색(조문번호/FTS/벡터/지역/
  사업유형/기준일/위계 필터), Claude 구조화 답변 + citationId 서버 재검증
- 사용자 챗봇 화면(`/chat`), 관리자 화면(`/admin`, `/admin/documents`, `/admin/reviews`)
- Vercel Preview 배포 대응: 빌드 시점 DB 미접근(`force-dynamic` + try/catch),
  `PREVIEW_READ_ONLY_MODE`, `/api/health`, `/api/ready`, Preview 가상 시드 데이터,
  Neon pgvector 수동 워크플로(`preview-db-setup.yml`)
- 개발용 사용자 선택 로그인(간이 로그인) — **운영에는 부적합**, Stage 2에서 교체 대상

이번 브랜치에서 `claude/production-auth-storage-v1`(별도 세션에서 이미 구현·테스트된
실제 인증/저장소 브랜치)을 병합해 아래를 추가로 반영했다:
- 실제 이메일/비밀번호 인증, Argon2id 해시, DB 기반 세션(`UserSession`), CSRF
  더블 서브밋 쿠키, 계정 잠금/실패횟수, 강제 비밀번호 변경, `sessionVersion` 기반
  전역 세션 무효화, 감사로그 기록
- `/admin/users` 사용자 관리 화면, `/account/security` 비밀번호 변경 화면
- `FileStorageProvider` 인터페이스 + `LocalFileStorageProvider`/`S3FileStorageProvider`
- 병합 충돌 8개 파일 수동 해결, typecheck 오류 2건 수정 완료(커밋 `faccd0f`)
- Stage 3 공격 시나리오 중 빠져 있던 "다운로드 URL 직접 입력", "감사로그 URL 직접
  입력" 두 시나리오에 대응하는 원본 파일 다운로드 API + 감사로그 조회 API/화면을
  신설(커밋 `e337140`)

## 2. 목표 상태 (v1.0 RC 완료 정의, 지시서 §1의 18개 항목)

1. 관리자가 법률/조례/유권해석/판례/내부자료를 안전하게 등록할 수 있다
2. 조/항/호 단위 한국 법령 구조를 정확히 파싱한다
3. 사용자가 지역/사업유형/절차단계/기준일로 질의를 필터링할 수 있다
4. 검색은 등록된 문서로만 엄격히 제한된다
5. 근거 없는 답변을 생성하지 않는다
6. 실재하고 검증된 citationId만 답변에 사용한다
7. 법령 위계(법률/시행령/조례/유권해석/내부자료)를 구분한다
8. 실제 이메일/비밀번호 인증과 역할 기반 권한이 동작한다
9. ADMIN/REVIEWER/USER가 서버 사이드로 강제된다
10. 내부자료(INTERNAL_MEMO)는 일반 사용자에게 절대 노출되지 않는다
11. 운영 환경 파일 저장소는 S3 호환 Object Storage를 지원한다
12. 로컬 개발은 Local Storage를 쓸 수 있다
13. Neon PostgreSQL+pgvector, Vercel에 배포 가능하다
14. GitHub Actions가 lint/typecheck/단위/통합/build를 자동 검증한다
15. 환경변수와 배포 방법이 문서화되어 있다
16. 의미 있는 보안/회귀/E2E 테스트가 존재한다
17. 핵심 기능을 휴대전화에서 사용할 수 있다
18. 외부 시크릿 키가 없을 때도 제한 모드로 동작하고 환각을 일으키지 않는다

## 4. 위험 요소

- **(해결됨) 마이그레이션 체인이 searchVector를 삭제하던 실제 버그**: 처음에는
  로컬 DB만의 이력 drift로 추정했으나, Stage 1 감사에서 완전히 새 DB에 마이그레이션
  체인을 처음부터 적용해 재현한 결과 **실제 버그**로 확인됐다 — 병합된
  `production_auth_and_sessions` 마이그레이션이 직전 마이그레이션이 추가한
  `searchVector` 컬럼/GIN 인덱스를 DROP하고 있어, Neon 최초 배포·CI·신규 클론 등
  **모든 신규 배포**에서 하이브리드 검색의 키워드/FTS 단계가 항상 실패하는 상태였다.
  신규 마이그레이션(`20260726123000_restore_legal_chunk_search_vector`)으로 복구,
  빈 DB에서 전체 체인 재적용으로 재검증 완료(`docs/JBOT_V1_STAGE1_AUDIT.md` #21).
  **교훈**: 로컬 DB 상태만으로 마이그레이션을 검증하지 말고, 반드시 빈 DB에
  `prisma migrate deploy`를 처음부터 실행해 확인할 것 — 이미 컬럼이 존재하는 DB에서는
  이런 종류의 버그가 절대 드러나지 않는다.
- Claude API 키 없이는 "5. Claude API 키가 설정된 경우..." E2E가 항상 skip된다 —
  실제 키를 넣어 수동 확인이 필요한 유일한 케이스.
- 병합으로 인해 두 브랜치가 각각 다른 시점에 작성한 로직이 섞여 있어, 자동 병합된
  파일도 반드시 직접 읽어 재확인해야 한다(이번 세션에서 `admin/layout.tsx`,
  `chat/page.tsx`, `schema.prisma`, `e2e/globalTeardown.ts` 전부 재확인 완료).

## 5. 외부 계정/시크릿이 필요한 항목 (BLOCKED_EXTERNAL 후보)

- 실제 운영 배포(Vercel 프로젝트 연결, Neon 프로덕션 DB 생성)는 사용자의 Vercel/Neon
  계정과 실제 자격증명이 필요하다 — 코드/설정/문서 준비까지만 이 브랜치에서 진행하고,
  실제 계정 연결/배포 실행은 사용자 확인 후 진행한다.
  실제 자격증명 없이는 계속 진행할 수 없다.
- 운영용 S3 호환 Object Storage(버킷 생성, 액세스 키 발급)도 동일하게 사용자 계정이
  필요하다. 코드(`S3FileStorageProvider`)와 문서는 이미 준비되어 있다.
  실제 자격증명 없이는 계속 진행할 수 없다.
- 실제 Claude API 키(운영 키)도 사용자가 직접 발급/입력해야 한다.
